## Implementation choices

| Choice                                                                                                                                                                                                                                                                                                                            | Why                                                                                                                                                                                                                        | Where                                                                                       |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| TypeScript pinned to `~6.0.3`, not 7.x                                                                                                                                                                                                                                                                                            | typescript-eslint 8.72 supports TypeScript `<6.1`.                                                                                                                                                                         | root and package `package.json` files                                                       |
| ESLint shared config lives in `packages/config/eslint.mjs`, not `eslint.config.mjs`                                                                                                                                                                                                                                               | ESLint 10 looks up the nearest `eslint.config.*` per file, so a shared file with that name would be picked up as the config for its own folder.                                                                            | `packages/config`                                                                           |
| Two database roles: `manorg_owner` (migrations, seed) and `manorg_app` (runtime)                                                                                                                                                                                                                                                  | The API role does not own the tables and has no `BYPASSRLS`, so RLS filters every query. Adds `DATABASE_MIGRATION_URL` beside the spec's `DATABASE_URL`.                                                                   | `infra/postgres/init`, `apps/api/prisma.config.ts`                                          |
| `organization_id` added to every org-scoped table, including child and join tables the spec lists without it (`punch_events`, `order_lines`, `team_members`, ...)                                                                                                                                                                 | CLAUDE.md rule 1.                                                                                                                                                                                                          | `apps/api/prisma/schema.prisma`                                                             |
| Orders, deliveries and their child rows keep `organization_id` = the bakery and also carry `contractor_org_id`                                                                                                                                                                                                                    | Lets one RLS policy show a row to both sides of the sale.                                                                                                                                                                  | orders, order_lines, deliveries, delivery_lines, delivery_change_requests, contractor_links |
| Child rows reference parents by a composite key that includes `organization_id`                                                                                                                                                                                                                                                   | Foreign-key checks bypass RLS, so a plain FK could link a row to another organization's parent.                                                                                                                            | `schema.prisma` relations                                                                   |
| `employee_id` columns reference the user id (no foreign key to memberships)                                                                                                                                                                                                                                                       | A user keeps one id across rejected and re-approved memberships; membership is checked in services.                                                                                                                        | shifts, punch_events, output_entries, ...                                                   |
| `ingredient_assignments` (not `ingredient_responsibilities`) and `ingredient_orders(ordered_by, packs)`                                                                                                                                                                                                                           | Spec section 7 lists both versions of these tables; the first listing is used. Needs confirming.                                                                                                                           | `schema.prisma`                                                                             |
| `tasks.assignee_id` is nullable                                                                                                                                                                                                                                                                                                   | Ingredient-order tasks go to the organization's admins, not one person (ING-5).                                                                                                                                            | `schema.prisma`                                                                             |
| No `end_time > start_time` check on `shifts`                                                                                                                                                                                                                                                                                      | SHF-1 says end must be after start, but section 4 allows a night shift that crosses midnight. Open for Phase 1.                                                                                                            | `shifts`                                                                                    |
| `version` column on tables admins edit                                                                                                                                                                                                                                                                                            | Supports If-Match and 409 conflicts (spec section 8).                                                                                                                                                                      | `schema.prisma`                                                                             |
| Prisma 7 with the `@prisma/adapter-pg` driver adapter; the generated client lives in `apps/api/src/generated` (git-ignored, built on install)                                                                                                                                                                                     | Prisma 7 requires a driver adapter.                                                                                                                                                                                        | `apps/api`                                                                                  |
| One endpoint for both kinds of application: `POST /organizations/{id}/applications`                                                                                                                                                                                                                                               | Without `X-Organization-Id` a person applies as an employee; with a contractor organization's id, its admin applies for that contractor (ACC-6).                                                                           | `organizations.service.ts`                                                                  |
| `POST /members` adds an existing account by email; there are no email invitations yet                                                                                                                                                                                                                                             | ACC-7 says admins create more admins; inviting people with no account needs email delivery, which is not in Phase 0.                                                                                                       | `members.service.ts`                                                                        |
| Wrong organization answers 404; right organization with too little permission answers 403                                                                                                                                                                                                                                         | Matches the kickoff's "wrong organization 404" and hides which organization ids exist.                                                                                                                                     | `org-context.guard.ts`                                                                      |
| A pending employee application is audited at account level (`organization_id` empty)                                                                                                                                                                                                                                              | The applicant is not in the organization yet, and RLS lets a row be written only inside the caller's organization. Approval and rejection are audited inside the organization.                                             | `organizations.service.ts`                                                                  |
| An organization always keeps one active admin (`LAST_ADMIN`, 409)                                                                                                                                                                                                                                                                 | Prevents locking everyone out of an organization; the admin rows are locked while checking.                                                                                                                                | `members.service.ts`                                                                        |
| `If-Match` is required on `PATCH /members/{id}` (428 when missing, 409 when stale)                                                                                                                                                                                                                                                | Spec section 8: edits send If-Match with the row version.                                                                                                                                                                  | `common/if-match.ts`                                                                        |
| `GET /applications` returns the whole pending queue as one page (`nextCursor: null`)                                                                                                                                                                                                                                              | The queue merges two tables and stays small; other lists page with `limit` and `cursor`.                                                                                                                                   | `applications.service.ts`                                                                   |
| Access tokens last 15 minutes; refresh tokens 30 days, rotated on every use; a reused refresh token revokes its whole family; a new password revokes all refresh tokens                                                                                                                                                           | Spec section 12: refresh-token rotation.                                                                                                                                                                                   | `auth/tokens.service.ts`, `me.service.ts`                                                   |
| Passwords need at least 10 characters; sign-in is limited to 10 requests per minute per client (`AUTH_RATE_LIMIT_PER_MINUTE`)                                                                                                                                                                                                     | Spec section 12: rate-limited login. The numbers are not in the spec.                                                                                                                                                      | `auth.schemas.ts`, `app.module.ts`                                                          |
| `openapi.yaml` is written by hand and is the source of truth; a contract test fails when routes and the file disagree                                                                                                                                                                                                             | Spec section 8. Request validation uses zod schemas in the API (CLAUDE.md rule 8); the contract test checks routes, auth, the organization header and documented error codes.                                              | `packages/contracts`, `test/api/contract.test.ts`                                           |
| Every GET in the contract carries `x-tenant-scoped`                                                                                                                                                                                                                                                                               | The tenant-isolation suite is generated from the contract and calls each one; an undeclared GET fails the suite.                                                                                                           | `openapi.yaml`, `test/api/tenant-isolation.test.ts`                                         |
| No notifications are sent yet for applications                                                                                                                                                                                                                                                                                    | Push and in-app notifications (spec section 9) come with the notifications work in Phase 1.                                                                                                                                | stub                                                                                        |
| Secret scan uses gitleaks with an allowlist for fixed development placeholders only                                                                                                                                                                                                                                               | Spec section 12.                                                                                                                                                                                                           | `.gitleaks.toml`, `.github/workflows/ci.yml`                                                |
| Phase 0 work is committed on the session branch `claude/artifact-session-ac7k5h`, one commit per step                                                                                                                                                                                                                             | The cloud session can push only to that branch; `feature/<id>-short-name` branches start with Phase 1 tickets.                                                                                                             | git history                                                                                 |
| Telegram Mini App accounts may have a null email and a null password hash until the person sets both in Settings. Identity is `users.telegram_user_id` after the server checks initData.                                                                                                                                          | Spec section 7 lists email on `users`. Telegram does not give the Mini App an email. A synthetic address would show up as a real sign-in id. Password login stays closed until a password exists.                          | `users`, `POST /auth/telegram`                                                              |
| The only Telegram users who become bakery admins are the ids in `TELEGRAM_BOOTSTRAP_ADMIN_IDS`. Removal sticks. A pending or active employee membership in that bakery is promoted on a later checked sign-in. A membership in another organization is not moved. Other Telegram users get an ordinary account and no membership. | The deployment's intended admin is Telegram user `5220814834`. That id is configuration, not a hardcoded bypass, and it is not a secret. An email or display name is not proof.                                            | `TelegramService.provision`, `docs/DEPLOYMENT.md`                                           |
| Production bootstrap organization time zone is `Asia/Tashkent` when `TELEGRAM_BOOTSTRAP_TIMEZONE` is set. The code default remains `Asia/Seoul`.                                                                                                                                                                                  | The shop is in Tashkent. The spec default is unchanged for every other organization.                                                                                                                                       | production `.env`, `env.ts`                                                                 |
| The public webhook stays `/api/telegram/webhook`. The API implements `/api/v1/telegram/webhook` and the proxy forwards the legacy path. Private messages get a Mini App pointer. Other updates are ignored.                                                                                                                       | The existing bot is registered on that URL with message updates only. The old command behavior was not in this repository and is not reimplemented.                                                                        | `nginx.conf`, `TelegramService.handleWebhook`                                               |
| Production compose project `shohona_prod` uses new volumes `shohona_prod_postgres` and `shohona_prod_redis`, publishes only `127.0.0.1:4317`, and does not run the demo seed.                                                                                                                                                     | Host port 5432 is a separate Postgres process and is not published or restarted. The previous punch-card app is disposable test code and is not migrated. Known `Password123!` accounts must not exist on the public host. | `infra/production`, `assertDemoSeedAllowed`                                                 |
| The previous punch-card bot is not a compatibility target. The new webhook answers private messages with the Mini App link and ignores everything else.                                                                                                                                                                           | The owner said that app and its SQLite data can be replaced. Preserving its commands would be new product scope.                                                                                                           | `TelegramService.handleWebhook`, `docs/DEPLOYMENT.md`                                       |
| Text files check out as LF, including on Windows with `core.autocrlf=true`. Production applies `01-roles.sh` from `db-init` on every start.                                                                                                                                                                                       | A CRLF shebang is `/bin/sh^M`. Postgres then keeps the data directory and skips init scripts, so the ManOrg roles are missing. `db-init` creates them again without deleting the volume.                                   | `.gitattributes`, `infra/production/scripts/db-init.sh`                                     |
