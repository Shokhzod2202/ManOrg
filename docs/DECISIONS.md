# Decisions

Every spec default (section 4 open questions) the code relies on, plus implementation choices the
spec leaves open. Change a row only together with the code that depends on it.

## Spec defaults relied on

| #               | Open question (spec section 4)                           | Default used                                                                                                                                                 | Where it is enforced                                                                                                                          |
| --------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 1               | Order cut-off time                                       | Superseded 2026-11-13: no fixed cut-off. Orders can be placed for any date from today on; changes after placing become change requests (see decisions below) | ORD-2, ORD-3 (to build)                                                                                                                       |
| 2               | Punch tolerance before red                               | 10 minutes, configurable                                                                                                                                     | `organizations.punch_tolerance_min` (default 10)                                                                                              |
| 3               | One user in several organizations?                       | One organization per user in v1                                                                                                                              | Partial unique index `memberships_one_open_per_user`; checked in the organizations, applications and members services                         |
| 4               | Sign-in method                                           | Email and password                                                                                                                                           | `POST /auth/register`, `/auth/login`                                                                                                          |
| 5               | UI languages                                             | English first; Korean and Uzbek later                                                                                                                        | `users.locale` accepts `en`, `ko`, `uz` (default `en`)                                                                                        |
| 7               | Is paused time paid?                                     | Unpaid                                                                                                                                                       | Not used yet (Phase 1 punch math)                                                                                                             |
| 10              | Contractor members besides admins?                       | Admins only in v1                                                                                                                                            | Applications to a contractor organization are refused; contractor admins add admins through `POST /members`                                   |
| 13              | Delivery window                                          | Superseded by DTM-1 to DTM-3 (spec 3.7a): a standing approximate time per contractor, copied onto each delivery when it is created                           | `deliveries.window_start`, `deliveries.window_end` hold the copy; `contractor_links.approx_start` / `approx_end` arrive with DTM-1 in Phase 1 |
| 14 (first list) | Ingredient ordering schedule format                      | Weekly day and time per ingredient                                                                                                                           | `ingredients.order_schedule_weekday`, `ingredients.order_schedule_time`                                                                       |
| Edge cases      | A rejected applicant may re-apply after 7 days (assumed) | 7 days                                                                                                                                                       | `assertReapplyAllowed` for employee and contractor applications                                                                               |

## Decisions from the product owner

| Date       | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Where it is enforced                                                                           |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 2026-11-12 | Employees never edit or place orders. What employees may read is set per organization by its admin in Employee access (`GET`/`PUT /organization/employee-access`): everyone's shifts and the orders due next start open (spec section 2, TOD-1 to TOD-7); the monthly orders list, deliveries, everyone's output, ingredient prices and finance start closed. A switch only ever opens read access. This replaces the spec section 2 "no" for employees on these reads and F-001's "employees have no access to financial data".                                                                                                                    | `employee-access.ts`, `permissions.ts` (`{ setting }` grants), `organizations.employee_access` |
| 2026-11-13 | The AI bot sees and does everything the provider admin can, including orders, the monthly orders list, payments, finance and settlements. This replaces spec section 2's narrower bot column and F-001's "no finance tools" (F9). Approving or rejecting applications, managing admins and roles, and changing Employee access are off by default and the admin can switch each on in Bot permissions (`GET`/`PUT /organization/bot-access`). The bot can never change Bot permissions or create or join organizations. Every bot write is still previewed and confirmed by the admin and audited; no bot tool deletes anything (CLAUDE.md rule 7). | `permissions.ts` (`BOT_BY_SETTING`, `BOT_NEVER`), `bot-access.ts`, `organizations.bot_access`  |
| 2026-11-13 | The monthly orders list and payment confirmations: provider admin (all), contractor admin (own), the bot, and employees only if the admin opens the area.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | `orders.readHistory`, `payments.view`                                                          |
| 2026-11-13 | Organizations that sell are **providers** (a bakery, a cake shop, any producer), not only bakeries. A contractor can buy from several providers, each approving it separately. The organization type `bakery` is renamed `provider`; the spec's "Bakery Admin" means the provider's admin.                                                                                                                                                                                                                                                                                                                                                          | `organization_type` enum, `actorFor`                                                           |
| 2026-11-13 | Ordering dates (to build with ORD-2): a contractor picks the delivery date from a calendar, any date from today on. Before 10:00 (provider time) the app asks whether the order is for today; from 10:00 it defaults to the next day, and the date stays editable. Orders for today are allowed, for example after midnight when the contractor forgot. This replaces "made the day before" in ORD-2.                                                                                                                                                                                                                                               | ORD-2 (to build)                                                                               |
| 2026-11-13 | Order changes (to build with ORD-3): once placed, a contractor's edit does not change the order. It becomes a change request that the provider admin and all employees see. Employees accept added products or larger quantities product by product, without the admin. Removed products and smaller quantities are approved by the admin only. This replaces "edits allowed until a cut-off" in ORD-3 and prevents unnoticed changes.                                                                                                                                                                                                              | ORD-3 (to build)                                                                               |
| 2026-11-13 | Night shifts (to build with SHF-1): a planned shift may end on the next day (for example 22:00 to 06:00), and each shift records its start date and end date explicitly so nobody misreads which night it is. This settles SHF-1 ("end after start") against the night-shift rule in section 4.                                                                                                                                                                                                                                                                                                                                                     | SHF-1 (to build)                                                                               |
| 2026-11-13 | Where the spec lists a table twice, the second version wins: `ingredient_responsibilities` and `PUT /ingredients/{id}/responsible`; `ingredient_orders.requested_by` and `quantity` (packs). `ingredient_orders` also keeps `note` and `fulfilled_by`/`fulfilled_at` from the first version, because ING-5 and ING-6 need them. Open questions 14 to 17 use the second list: team output counts once and each member is credited an equal share; ordering schedule is a weekly day and time; the admin places the real supplier order outside the app; a team is private to its creator and its members see lines logged for them.                  | `schema.prisma`, `ingredients.controller.ts`                                                   |
| 2026-11-13 | Virus scanning of uploads is added before launch, not now; uploads are already limited to real JPEG, PNG and WebP pictures of at most 5 MB.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | open                                                                                           |
| 2026-11-13 | Telegram comes alongside the phone app, not instead of it: a Telegram bot sends notifications and a Telegram Mini App offers the screens inside Telegram. The Expo phone app stays for features Telegram cannot do (location-based start-shift reminders, camera-only task photos).                                                                                                                                                                                                                                                                                                                                                                 | to build (notifications)                                                                       |
| 2026-11-13 | Same-day orders: a contractor can order for today until that contractor's delivery for today is marked completed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | ORD-2 (to build)                                                                               |
| 2026-11-12 | Ingredient prices are whole won (as F-001 does for product prices) and stay editable. An edit adds a price effective from that moment, so it only changes future calculations; an ingredient order keeps the price in force when it was placed.                                                                                                                                                                                                                                                                                                                                                                                                     | `ingredient_prices` (append-only history), `ingredient_orders.pack_price`                      |

| ESLint shared config lives in `packages/config/eslint.mjs`, not `eslint.config.mjs`                                                                                                                                                                                                                                                                                                                                | ESLint 10 looks up the nearest `eslint.config.*` per file, so a shared file with that name would be picked up as the config for its own folder.                                                                                                                          | `packages/config`                                                                           |
| Two database roles: `manorg_owner` (migrations, seed) and `manorg_app` (runtime), neither a superuser                                                                                                                                                                                                                                                                                                              | The API role does not own the tables and has no `BYPASSRLS`, so RLS filters every query; the owner is not a superuser, so forced RLS applies to it too. Docker's `postgres` superuser only creates them. Adds `DATABASE_MIGRATION_URL` beside the spec's `DATABASE_URL`. | `infra/postgres/init`, `apps/api/prisma.config.ts`                                          |
| `organization_id` added to every org-scoped table, including child and join tables the spec lists without it (`punch_events`, `order_lines`, `team_members`, ...)                                                                                                                                                                                                                                                  | CLAUDE.md rule 1.                                                                                                                                                                                                                                                        | `apps/api/prisma/schema.prisma`                                                             |
